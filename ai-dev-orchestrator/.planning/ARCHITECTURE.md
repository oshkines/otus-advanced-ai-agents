# Архитектура: AI Dev Orchestrator (Windows Native)

> Источник: перенесено из `docs/architecture.md` (26.10.2026) без изменения смысла;
> раздел «Реализация в коде» добавлен по фактическому состоянию репозитория.

## Компоненты системы

1. **C++20 Core (Управляющий):** Консольное приложение, собирается через CMake + MSVC 2022. Читает конфиг `config/orchestrator.json`. Запускает Python-воркеры по расписанию.
2. **Python 3.11+ Workers (Исполнители):** Скрипты в папке `agents/`. Общаются с ядром через JSON в `stdout`.
3. **БД SQLite3:** Локальный кэш ID сообщений/писем, чтобы не слать дубли и экономить ИИ-токены.

## Поток данных

```
config/orchestrator.json
        │  (читается при старте)
        ▼
  C++20 Core (core/)  ──schedule/tick──►  Python Worker (agents/*.py)
        │                                        │
        │◄────────── JSON в stdout ──────────────┘
        │
        ├──► SQLite3 кэш (data/cache.db): дедупликация ID сообщений/писем
        └──► src/status_panel.html: отображение статусов
```

## Контракт «ядро ↔ воркер»

- Воркер запускается как отдельный процесс интерпретатором из поля `interpreter` (по умолчанию `python`).
- Результат — **только** JSON в `stdout` (`stdout_format: "json"`), диагностика — в `stderr`.
- Ограничение времени выполнения — `timeout_sec` из конфига (180 с для сканера, 120 с для Telegram).
- Если воркеру нужны секреты, они перечислены в `env_required` (только имена переменных, значения — из окружения Windows).

## Технологические ограничения (зафиксированы)

- Платформа: **Windows 11 native**, MSVC 2022 + CMake, **без WSL**.
- Python: 3.11+ (в проекте развёрнут 3.12.14 в локальном `.venv`).
- E2E: Playwright **for Python** (Node.js не используется).
- Секреты: только переменные окружения, файлы `.env` агентам читать запрещено (см. `.planning/SECURITY.md`).
