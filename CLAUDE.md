# Инструкции для ИИ-агентов (AI Dev Orchestrator)

> 🧯 **Перед диагностикой любой ошибки** сначала открой [`docs/troubleshooting.md`](docs/troubleshooting.md) — это журнал уже решённых проблем (симптом → причина → решение → профилактика). Если такой проблемы там нет — реши её и **допиши запись в конец журнала** по шаблону из него.
>
> ⚠️ **Частая ловушка:** нельзя запускать `npm run build` в `web/`, пока работает `next dev` на порту 3000 — оба используют каталог `web/.next`, и после сборки dev начинает отдавать `500 Internal Server Error` (лечение — запись 001 в журнале).

## 🎯 Роль и Цель (Goal)
Ты — Senior C++ и Python разработчик, создающий легковесную утилиту автоматизации рутины и мониторинга. Проект является учебным полигоном для обкатки AI-агентов, MCP-серверов и мультиагентного взаимодействия.

## 🛠️ Технологический стек проекта
- **Языки:** C++20 (консольные модули), Python 3.11+ (скрипты автоматизации и парсинга)
- **Библиотеки Python:** `telebot` / `aiogram`, `beautifulsoup4`, `requests`
- **Сборка C++:** CMake, vcpkg
- **Окружение ИИ:** VS Code + Cline + DeepSeek Harness (с MCP-серверами)

## 🚫 Ограничения и Правила (Constraints)
- **Стиль кода:** Только чистый и понятный код. В C++ используем современные стандарты смарт-указателей. В Python — строгую типизацию (typing annotations).
- **Безопасность конфигурации:** Категорически запрещено хардкодить токены Telegram, пароли и API-ключи. Все параметры считывать из переменных окружения (.env) или защищенных JSON-конфигов.
- **Интерфейс командной строки:** Все CLI-выводы агентов должны быть информативными, структурированными, содержать временные метки (timestamps).

## 🔁 Обязательный цикл проверки UI (`web/`)

Правило владельца проекта: **после любых правок фронтенда сервер должен быть поднят** — иначе
результат нельзя посмотреть в браузере (`ERR_CONNECTION_REFUSED` на `localhost:3000`).

1. Правишь `web/**` → поднимаешь `npm run dev` в `web/` и убеждаешься, что `GET http://localhost:3000/` = 200.
2. Сервер **оставляешь работающим** до конца сессии; в ответе пишешь порт и факт проверки (HTTP 200).
3. Нужен production-вид (скриншот, сверка с README) → сначала гасишь dev (ловушка с `.next` выше),
   затем `npm run build` + `npm run start:e2e` (:3100); после съёмки возвращаешь dev.
4. Проверка «жив ли сервер»:

   ```powershell
   Get-NetTCPConnection -LocalPort 3000 -State Listen |
     Select-Object -ExpandProperty OwningProcess -Unique
   ```

   Пусто → сервер погашен, подними заново **перед** отчётом, а не после просьбы пользователя.

## 🎯 Правила использования автономных навыков (SKILLs)

При получении кастомных слэш-команд в чате, строго руководствуйся инструкциями из физических файлов артефактов:

*   **При вызове команды `/review`:**
    1. Немедленно прочитай содержимое файла `skills/code-review/SKILL.md`.
    2. Выполни аудит измененного или выбранного кода строго по чек-листу из этого файла.
    
*   **При вызове команды `/testgen`:**
    1. Немедленно прочитай содержимое файла `skills/test-generation/SKILL.md`.
    2. Сгенерируй модульные тесты для указанного компонента, соблюдая заложенные там требования к граничным условиям и архитектуре.

*Запрещено игнорировать инструкции из папки `skills/` или подменять их логикой по умолчанию.*
